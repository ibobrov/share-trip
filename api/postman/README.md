# Postman: ShareTrip

Импортируйте `ShareTrip.postman_collection.json` в Postman (Collection v2.1).
Коллекция содержит 19 запросов: прикладные HTTP-маршруты ShareTrip, Contract
и Notification, метрики трёх сервисов, спецификацию Contract OpenAPI и два
запроса токенов Keycloak. API управления инфраструктурой в неё не входит.

## Подготовка и запуск

1. Запустите локальный Kubernetes-стенд: `make k8s-up`.
2. На вкладке Variables коллекции задайте локальные значения `client_secret`,
   `username` и `password`. Не коммитьте и не передавайте экспорт с секретами.
3. Выполните **Get tokens (password)**. Запрос сохранит `access_token`,
   `refresh_token`, `company_id` и `recipient_id` (значение `sub` из токена)
   в переменные коллекции. У пользователя должны быть роль `client`
   в клиенте `sharetrip-api` и атрибут `company_id` в токене.
4. Для новой компании выполните **Create contract**, затем **Activate contract**.
   Пример включает все четыре услуги. Если активный договор уже есть,
   используйте **Get active contract**: активация второго договора вернёт 409.
5. Выполните **Create trip**, **Publish trip**, затем **Get trip**. ID поездки
   сохраняется автоматически. Проверки допускают первую публикацию (201)
   и повторную (200).
6. Запросы уведомлений можно выполнять отдельно. **Create notification**
   сохраняет `notification_id` для **Get notification**. Это ручное создание
   записи, которое не проверяет доставку через Kafka. Публикация поездки
   асинхронно создаёт отдельное уведомление; HTTP-метода поиска или получения
   списка уведомлений сейчас нет.

Запускайте отдельные запросы или выбранные папки. Полный запуск коллекции
каждый раз создаёт записи и пытается активировать новый договор, поэтому
повторный запуск для существующей компании не является идемпотентным.
**Refresh tokens** выполняется по необходимости.

Проверки ожидают успешные HTTP-коды, а для прикладных POST-запросов и запросов
поездок — также пустой массив `errors`: HTTP 200 может содержать доменную ошибку.

## Переменные

| Переменная | Назначение |
| --- | --- |
| `sharetrip_url` | `http://localhost:38080` |
| `contract_url` | `http://localhost:38082` |
| `notification_url` | `http://localhost:38081` |
| `keycloak_url` | `http://localhost:38087` |
| `realm`, `client_id` | `sharetrip`, `sharetrip-api` |
| `client_secret`, `username`, `password` | Локальные учётные данные Keycloak; в файле пустые |
| `access_token`, `refresh_token` | Сохраняются из ответа Keycloak; в файле пустые |
| `company_id`, `recipient_id` | Сохраняются из JWT; можно задать вручную |
| `contract_id`, `trip_id`, `notification_id` | Сохраняются из успешных ответов создания |
| `starts_at` | Если пустая, задаётся время на минуту раньше текущего; RFC3339 |
| `departure_time` | Если пустая, задаётся время через семь дней; RFC3339 |
| `correlation_id` | Генерируется один раз, если пустая; связывает запросы сценария |

Очистите `departure_time`, чтобы обновить устаревшую дату поездки.
Очистите `correlation_id`, чтобы начать новый сценарий трассировки.
Каждый запрос получает новый `X-Request-ID`. Скрипты работают с переменными
коллекции; избегайте одноимённых переменных окружения: они перекроют значения.

Запросы поездок передают `X-Refresh-Token`, как требует текущий middleware.
Одного Bearer-токена для этих маршрутов недостаточно. Метрики и запросы
Contract и Notification в текущем коде не требуют токена. Если ротация токенов
Keycloak сделала refresh-токен недействительным после запроса поездки,
получите новые токены перед следующим запросом.

## Учётные данные и экспорт

В сохранённой коллекции `client_secret`, `username`, `password`, `access_token`
и `refresh_token` пустые. Запросы используют ссылки на переменные,
сохранённых примеров ответов с токенами нет. `realm` и `client_id` —
идентификаторы конфигурации, а не секреты.

После выполнения запросов токены записываются в переменные коллекции.
Перед экспортом для передачи или коммита очистите учётные данные и токены,
а также идентификаторы компании, получателя и созданных записей.
Повторно проверьте экспортированный JSON: исходный файл в проекте
не обновляется автоматически при изменении значений в Postman.

## Источники и проверка

Источники: обработчики и маршруты ShareTrip в этом репозитории,
`share-trip-contract/api/contract.yaml` и обработчики Notification
в соседних Go-проектах. Структура JSON, тела запросов и синтаксис скриптов
проверены локально. Запросы к запущенному стенду не выполнялись.
